Using the correct table can improve prompt processing speed by 1.5x to 2x.
*   **Kernel Optimizations:** Specific switches like `STRATA_DENSE_MMQ` (using int8 kernels for dense projections) and `STRATA_HIP_WMMA` (using matrix cores on RDNA4) are detailed. These can significantly boost prompt throughput but may alter numerical precision, leading to slight divergences in greedy output compared to the default path.
*   **Legacy Support:** The text also covers support for older architectures like gfx906 (Instinct MI50), which requires a specialized build using a CUDA-to-HIP compatibility layer, as standard ROCm releases no longer support these cards.

#### Model Selection and Memory Requirements

Strata supports several quantized versions of the Qwen3.8-Flash-Next model:
*   **Q2_0:** Fastest, requires ~34 GB RAM for experts.
*   **IQ2_XS:** Slightly better quality, similar speed.
*   **IQ3_XXS:** Best quality, slower, requires ~43 GB RAM.
*   **Coder:** A pruned version with half the experts, optimized for coding tasks, running on 32 GB RAM.
*   **Swift 1.5:** A fine-tune designed to reduce "thinking" tokens, offering faster answers with minimal accuracy loss.

The engine employs sophisticated memory management strategies:
*   **Low-RAM Mode:** For systems with insufficient RAM to hold all experts, Strata can map experts from disk (`--mmap-experts`) or use a resident RAM budget (`--resident-experts`).
*   **KV Streaming:** For long contexts (64K+), the KV cache is kept in system RAM, with only a window resident in VRAM, allowing more experts to fit on the GPU.
*   **Expert Caching:** The engine dynamically swaps experts between VRAM and RAM based on usage patterns (`--adapt-every`).

#### Multi-GPU and Batching

Strata supports splitting model layers across multiple GPUs (`--layer-split`). This is particularly useful when a single card cannot hold all model experts.
*   **Layer Split:** Layers are divided between cards. The documentation notes that splitting is only beneficial if the combined VRAM holds more experts than a single card. If one card can hold all experts, splitting often results in slower performance due to inter-GPU communication overhead.
*   **Batching (`--batch`):** Strata can serve multiple requests concurrently by decoding them in parallel windows. This reduces latency for multiple users but may reduce per-request throughput on cards with limited VRAM, as batch slots consume VRAM that would otherwise be used for expert caching.

#### API and Integration

Strata exposes an OpenAI-compatible API (`/v1/chat/completions`) and an Anthropic-compatible API (`/v1/messages`). It also supports the newer OpenAI Responses API for tools like Codex CLI.
*   **Features:** The API supports streaming, tool calling (including MCP servers), reasoning effort levels (none, low, medium, high), and thinking budgets.
*   **Conversation Caching:** The engine maintains checkpoints of conversations to avoid re-reading prompts. It supports session files for saving and restoring state across restarts.
*   **Vision:** Optional vision support is available via a separate encoder, which can run on the GPU or CPU.

#### Experimental Features and Troubleshooting

The documentation highlights several experimental or opt-in features:
*   **Speculative Decoding:** Uses a draft layer to propose tokens, which are then verified by the main model. Switches like `STRATA_SPEC_COUPLED` and `STRATA_SPEC_GUMBEL` aim to improve draft acceptance rates.
*   **Memory Reclaim Issues:** On Linux, kernel memory reclaim can suspend GPU queues, causing timeouts. Workarounds include setting `HSA_USERPTR_FOR_PAGED_MEM=0` or using `--mmap-experts` with specific pinned memory settings.
*   **VRAM Elasticity:** An experimental feature allows dynamically shrinking the expert cache to free VRAM for other applications, at the cost of slower inference.
